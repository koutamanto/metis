# Metis — 作業環境チュートリアル

ここまで構築してきた読み上げ・パネル・脳内ステート・画面観測・Quick Action 一式は
まとめて **Metis**（拡張人工知能インターフェイス）と呼びます。メニューバーの一番上にも
この名前が出ます。

このファイルは、家庭教師役の Claude Code セッションが読む台本です。
**一度に1ステップだけ**提示し、実際に試して結果を報告してもらってから次へ進めてください。
確認できるものは家庭教師側でコマンドを実行して裏を取ってから進めてください。

---

## STEP 0 — 権限の付与（これだけは手作業）

Hammerspoon と AeroSpace は、macOS の権限が無いと**何も動きません**。ここが最初の関門です。

1. **システム設定 → プライバシーとセキュリティ → アクセシビリティ**
   `Hammerspoon` と `AeroSpace` を追加して有効化
2. **同 → 画面収録とシステムオーディオ録音**
   `Hammerspoon` を追加して有効化（画面観測に必要）
3. 有効化したら Hammerspoon を再起動（メニューバーのアイコン → Reload Config）

**確認方法**: メニューバーに `◉` が出ていれば画面観測が生きています。
`⌘⌥M` を押して脳内ステートのオーバーレイが出れば、ホットキーも通っています。

権限がまだなら、STEP 1〜3 は権限なしで動くのでそちらを先に進めても構いません。

## STEP 1 — シェルの基礎（権限不要・今すぐ使える）

新しいターミナルを開いて、順に試してもらってください。

| 試すこと | 何が起きるか |
|---|---|
| `ll` / `lt` | eza によるアイコン付き一覧 / ツリー表示 |
| `cat ~/.zshrc` | bat による行番号＋シンタックスハイライト |
| `cd cla` と打って Enter | zoxide が学習済みの場所へジャンプ（初回は普通の cd） |
| `Ctrl+T` | fzf でファイル検索。右にプレビューが出る |
| `Alt+C` | fzf でディレクトリ検索して移動 |
| `Ctrl+R` | atuin の履歴検索。過去の全ディレクトリから fuzzy 検索できる |
| `↑` を押す前に `git` と打ってから `↑` | 前方一致で履歴を絞り込む |

**つまずきやすい点**: 旧 `rg`（rails generate）は ripgrep と衝突するため **`rgen`** に改名済み。

## STEP 3 — tmux 母艦（ここから本題）

Claude Code を tmux の中で走らせると、**ウィンドウを閉じてもセッションが死にません**。

```sh
mkdir -p ~/dev/sandbox && cw ~/dev/sandbox    # セッションを作って claude を起動
```

`cw` の中で Claude に何か長めの作業を頼んだら、**ターミナルウィンドウを閉じてみてください**。
新しいウィンドウで `cl` を実行すると、さっきのセッションがまだ生きていて、選ぶと戻れます。

| コマンド | 動作 |
|---|---|
| `cw <パス>` | そのプロジェクト用セッションを作って入る |
| `cl` | 走行中セッションを fzf で選んで移動 |
| `cq` | 「待ち」状態のセッションだけ表示 |
| `cj` | 次の「待ち」セッションへジャンプ（連打で巡回） |
| `cr <名前> <テキスト>` | 画面を切り替えずに、そのセッションへ一言送る |

**`cr` を必ず試してもらってください。** これが切り替えコストを一番下げます。
別セッションが許可待ちのとき、今の画面から `cr sandbox 続けて` と打つだけで返事ができます。

## STEP 4 — 読み上げ（可視判定を体感する）

2つのセッションを走らせて、**片方を見ている状態で、もう片方を完了させてください**。

- 見えているセッション → **喋りません**（見えているものを喋るのは邪魔なだけ）
- 裏のセッション → 「プロジェクト名、完了」と読み上げます
- 確認待ちのときは別の声（Otoya）で「確認待ちです」

| 操作 | 動作 |
|---|---|
| `⌘⌥.` | 読み上げを今すぐ止める |
| メニューバー → 読み上げ | オン/オフ切り替え |

声や速度は `~/.claude/voice-config.json` で変えられます。

## STEP 5 — HUD とジャンプ

`⌘⌥H` で画面右上に半透明の一覧が出ます。3つくらいセッションを走らせて眺めてもらってください。

```
● sandbox     実行中  2m
◆ rails-app   確認待ち     ← ここが黄色
✓ docs        完了   5s
```

`⌘⌥J` で「待ち」のセッションへ一発で飛べます。連打すると待ちセッションを順に巡回します。

## STEP 6 — Quick Action

どのアプリでもいいので**テキストを選択**してから試してもらってください。

| キー | 動作 | 目安 |
|---|---|---|
| `⌘⌥A` | 選択テキストに即答（Sonnet 5 / 最速）→ 通知＋クリップボード | 5秒前後 |
| `⌘⌥⇧A` | 深掘り（Opus / high）→ 専用パネルへ | 20秒前後 |
| `⌘⌥S` | コマンドを生成 → **確認ダイアログ** → バックグラウンド実行 | 10秒前後 |

**右クリックからも同じことができます**: テキスト選択 → 右クリック → サービス →
「Claude に聞く」/「Claude コマンド生成・実行」

`⌘⌥S` は最初に安全な題材で試してください。例:「このディレクトリのファイルを大きい順に表示」

> **確認ダイアログについて**: 生成されたコマンドがダイアログに出るので、Enter で実行、
> その場で編集も可能です。任意のテキストから作ったコマンドを無確認で走らせるのは危険なので、
> 既定では必ず挟まります。慣れたら `~/.claude/quick-config.json` の `confirm` を false にできます。
> 実行内容は全件 `~/.claude/quick-log/` に残ります。

**STEP 6.5 — 画面の指示をそのまま実行する（⌘⌥X）**

`⌘⌥A`/`⌘⌥S` は選択テキストが対象でしたが、`⌘⌥X` は**フォーカス中のウィンドウをそのまま撮影**し、
そこに書かれた手順（このチュートリアルのような番号付き指示など）を読み取ってコマンド化します。

1. `⌘⌥X` を押す
2. 抽出されたコマンド一覧が**1回のダイアログ**にまとめて出るので、内容を確認
3. 「この順に実行」で確定すると、新規ターミナルが開いて上から順に実行される

危険と判断したコマンド（`rm -rf` など）はダイアログに出る前に自動で除外されます。
除外されたかどうかは実行後に `~/.claude/quick-log/` のログで確認できます。

> **ショートカット早見表**: `⌘⌥/`（GitHub の `?` に相当）でこの環境の全キーバインドが
> 中央に一覧表示されます。Ghostty・tmux・AeroSpace・Hammerspoon の4層にキーが分散しているので、
> 迷ったらまずこれを開いてください。

**STEP 6.6 — Metis パネル（結果の一元管理）**

`⌘⌥A` や `⌘⌥S` を押すと、通知が出る前に**画面右上に自動でパネルが現れ**、
「考え中…」と表示されます。回答が届くとその場で埋まります。手動で何かする必要はありません。

- 複数の Quick Action を続けて叩くと、パネルに履歴として積み上がります
- 全部が完了してからしばらく（既定9秒）操作が無いと自動で閉じます
- `⌘⌥Q` でいつでも開閉でき、このときは自動では閉じません（履歴をゆっくり読める）

実測の応答時間自体（Sonnet 5・低 effort で概ね2〜3秒）は変わりませんが、
トリガーした瞬間に「動いている」ことが見えるので待たされている感覚が減ります。
常駐プロセスでセッションを使い回して起動コスト自体を削る方式も検討しましたが、
検証の結果フックの標準入力まわりで無応答になる再現性のある問題があり採用を見送りました。

**STEP 6.7 — Shot（画面を見ながら質問）**

`⌘⌥V` を押すと、フォーカス中のウィンドウを1枚撮影し、続けて「何について聞きますか？」
という小さな入力欄が出ます。空のまま確定すると「この画面に写っているものを説明して」が
既定の質問になります。回答は他の Quick Action と同じく Metis パネルに出ます。

- 撮影は `⌘⌥C`（画面観測の手動記録）や `⌘⌥X`（マクロ）と同じ除外リストに従うため、
  パスワード管理アプリなどを見ているときは撮影自体をしません
- 画像は質問への回答が終わった時点で即座に削除されます（保存され続けません）
- 使い方の例:「このエラーメッセージは何？」「このグラフから何が読み取れる？」

## STEP 7 — 脳内ステート

Obsidian 的なツールが続かないのは、**書く手間が便益を上回るから**です。
ここでは「書くのは一行だけ、整理は自動」にしています。

| キー | 動作 |
|---|---|
| `⌘⌥N` | 一行メモを放り込む（分類不要・思いついたまま） |
| `⌘⌥M` | 「今 / 次にやること / 保留 / ゴール」をオーバーレイで読み出す |

**やってもらうこと**: `⌘⌥N` で断片を3つほど放り込む（例:「〇〇のバグを直したい」
「××の設計を決めかねている」「明日までに△△」）。そのあと `⌘⌥M` を開くと、
Sonnet 5 が構造化した状態になっているはずです。

| コマンド | 動作 |
|---|---|
| `mind show` | ターミナルで状態を見る |
| `mind note <テキスト>` | メモを追加 |
| `mind sync` | 今すぐ再構成する |

真実の源は追記のみの `~/.claude/mind/journal.jsonl` で、`state.json` はそこからの導出物です。
おかしくなったら `mind sync` でいつでも作り直せます。

## STEP 8 — 画面観測（プライバシーの設計を必ず説明すること）

**メニューバーのアイコンが現在のモードです。**

| 表示 | 意味 |
|---|---|
| `◉` | セーフモード（既定）— **フォーカス中のウィンドウだけ**を撮る。背面は一切写らない |
| `◎` | ダイレクトモード — 全画面を10秒間隔で撮る |
| `○` | 停止 |
| 末尾に `✕` | 今見ている画面が除外対象なので撮っていない |
| 末尾に `·` | 無操作が続いているので一時停止中 |

**設計の要点を必ず伝えてください:**
- 撮影の起点は**ウィンドウのフォーカス切替**。同じ画面で作業し続けている間は90秒間隔で拾う程度
- **無操作が45秒続くと、撮影も解析も完全に止まります**。次に手を動かすまでゼロ
- パスワード管理・メッセージ・メール・ビデオ会議・音楽・Finder など32種のアプリは撮りません
- タイトルに「シークレット」「パスワード」等を含むウィンドウも撮りません
- 画像はローカルの `~/.claude/eye/` にのみ保存され、12時間で自動削除されます
- メニューバーの「撮影済みフレームを今すぐ消す」でいつでも即座に全消去できます

| キー | 動作 |
|---|---|
| `⌘⌥C` | 今の画面を記録して即解析（明示的に「これを覚えておいて」と言うとき） |

**やってもらうこと**: `⌘⌥C` を押して数十秒待ち、`⌘⌥M` を開く。
「今」の欄が画面の内容を反映していれば成功です。

除外設定は `~/.claude/eye-config.json` で足せます。

## STEP 9 — AeroSpace（ワークスペース）

| キー | 動作 |
|---|---|
| `Alt+1〜4` | ワークスペース切替（1=エディタ / 2=Claude群 / 3=ブラウザ / 4=雑用） |
| `Alt+Shift+1〜4` | 今のウィンドウを別ワークスペースへ送る |
| `Alt+Tab` | 直前のワークスペースへ戻る |
| `Alt+H/J/K/L` | フォーカス移動 |
| `Alt+F` | 全画面 |
| `Alt+R` | リサイズモード（h/j/k/l で調整、Enter で抜ける） |

**確認してもらう点**: ターミナル内で `Option+数字` を使う場面があるか。
衝突するなら `~/.config/aerospace/aerospace.toml` の `alt-1` を `ctrl-alt-1` に変えます。

## STEP 10 — セッションの枝分かれ

今このチュートリアルセッション自体が、環境構築セッションからの枝です。

| コマンド | 動作 |
|---|---|
| `croot` | 今のセッションを「根」として記録 |
| `cfork <名前> [初期プロンプト]` | 根から枝分かれした新しいセッションを tmux 内に作る |
| `ctut` | チュートリアル用の枝を作る（これ） |

枝は根の会話を丸ごと引き継ぐので、**前提の説明が一切要りません**。
「この設計のまま別方向を試したい」というときに、根を汚さずに分岐できます。

## 仕上げ — 自分の運用に馴染ませる

一通り触ったあと、家庭教師役は以下を聞いてください。

1. うるさすぎた通知・読み上げはあったか → `voice-config.json` を調整
2. 押しにくかったホットキーはあったか → `~/.hammerspoon/init.lua` の `MASH` を変更
3. 画面観測のモードは、普段どちらで運用したいか
4. `next` に出てくる提案は的を射ていたか → 外していれば `mind-config.json` の `journal_window` を調整

調整はその場で実施し、`⌘⌥⌃R` で反映してください。
